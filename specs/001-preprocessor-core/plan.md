# Technical Plan: Preprocessor core & pipeline

**Spec:** `specs/001-preprocessor-core/spec.md` · **Status:** Draft

## 1. Approach

A single-pass, region-based scanner with a shallow C context tracker. The scanner
walks the source producing an alternating stream of `CRegion` (verbatim bytes)
and `SqlConstruct` (keyword, opaque token body, host-variable reference list,
source span). It never parses C expressions and never parses SQL beyond the
leading keyword, host-variable references, and the constructs 004/006/007 claim.

Position class (Q1) is decided without a C parser by tracking three cheap
signals: brace depth, whether the last non-comment token was a statement
terminator or a block boundary, and whether we are inside a parameter list. A
construct at brace depth 0 is file-scope declaration position; at depth > 0 it is
declaration position if every preceding token in the current block is part of a
declaration, executable position otherwise. This is the same heuristic real
C-with-SQL preprocessors use; it accepts a small set of pathological inputs that
a full parser would reject, which is acceptable because misclassification
produces a diagnostic (FR-001.14), never wrong code. The heuristic's failure
modes are enumerated in the test suite as known-accepts.

Emission is textual and streaming: `CRegion`s are written unchanged;
`SqlConstruct`s are replaced by generated code from the owning feature's handler,
bracketed by `#line` directives that restore the original file and line
immediately after each replacement. This is what makes FR-001.18 cheap — the
generated block's own line count never has to match the source's.

## 2. Alternatives rejected

| Alternative | Why rejected |
|-------------|--------------|
| Full C parser front end (e.g. a real C99 grammar) | Correct position classification is worth far less than the cost: the project would own a C parser, and customer code uses vendor extensions and non-standard headers that would need supporting. Misclassification is a diagnostic, not a wrong answer, so exactness is not required. |
| Two passes: extract SQL, then reinsert | Doubles the bookkeeping for line fidelity and makes `SQL SOURCE` inclusion order harder to get right. |
| Parse SQL statement bodies fully | The manual defers syntax to `SQLRM`, which this project does not have. Owning an SQL/MP grammar is a larger project than the preprocessor. Opaque bodies (NFR-001.1) push translation to the runtime, where a real SQL parser (MariaDB's) already exists. |
| Reuse an existing open-source ESQL preprocessor | Their embedding rules, pragma handling, and structure layouts are all different. Adapting one costs more than the scanner, which is a few thousand lines. |

## 4. Runtime ABI surface

This feature adds **no** runtime entry points. It emits calls defined by 003 and
later; during Phase 1 it emits against the stub only.

The one contract this feature does own is the **handler interface** the other
features implement, which is internal, not ABI:

```c
typedef struct {
    const char *keyword;          /* leading SQL keyword, uppercased        */
    esqlc_pos_class_t position;   /* DECL | EXEC | ANY                      */
    int (*emit)(const esqlc_construct_t *, esqlc_emit_ctx_t *);
    const char *owning_feature;   /* "004", "007", ... for ESQLC-1012       */
} esqlc_handler_t;
```

## 5. Data structures

No SQL structures are generated by this feature, so Constitution VI imposes
nothing here. Internal structures are not layout-sensitive.

The one invariant worth asserting in code: `esqlc_construct_t` spans must
satisfy `body_end > body_start` and both must index the *original* buffer, not a
copy, so that diagnostics and `#line` cannot drift apart.

## 7. Test strategy

- **Golden-file preprocessor cases**: `tests/conformance/001/*.sqlc` each paired
  with `*.expected.c`. Assertions are on emitted runtime calls and `#line`
  directives; incidental whitespace is normalised before comparison.
- **Negative cases**: `tests/conformance/001/negative/*.sqlc` each paired with
  `*.expected.diag` containing code, line, and column. A negative test that
  produces the right code at the wrong position fails.
- **Line fidelity**: compile the emitted C with a deliberate error and assert the
  reported line, using the real C compiler rather than inspecting `#line` text.
- **Fixtures**: none require a database in this feature. Fixtures must avoid
  `=name` TACL DEFINEs until `DIV-002` is resolved (see ROADMAP standing risks) —
  use fully-qualified plain table names.

## 8. Risks

| Risk | Impact | Mitigation |
|------|--------|------------|
| Position-class heuristic misclassifies real customer code | False rejections; customer must edit source, violating Principle II in spirit | Build a corpus of position-class edge cases as tests; make the heuristic's accepts/rejects explicit; provide a pragma to suppress the check per-construct as an escape hatch (opt-in, so Principle II holds) |
| Opaque statement bodies push a parsing problem to the runtime that turns out not to be solvable there | Rework of NFR-001.1 across 004 and 007 | Prove the approach in Phase 1 with `INSERT … VALUES (:hv)` end to end before 004 starts; that path exercises host-variable substitution into an opaque body |
| `#line` interaction with the C compiler's own preprocessor | Line numbers drift after macro expansion | Test against the actual target compiler, not by inspection; pin the compiler in CI |
| `SQL SOURCE` recursion or cycles | Infinite loop | Inclusion depth limit and cycle detection in `source.c`, with a diagnostic |

## 9. Divergences introduced

None yet. Q2 (the `#pragma SQL` option set frozen to the six documented options)
becomes `DIV-003` if and when `CPG` is obtained and contradicts the freeze.
