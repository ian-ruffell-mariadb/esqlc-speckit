# Status

As of 2026-09-03, after ten merged slices (Gates 1–10). This document is the
honest inventory: what compiles and is proven, what is specified and unbuilt,
and what is blocked on documents this project does not have.

Companion documents: [ROADMAP.md](../ROADMAP.md) for phase order and standing
debts, [traceability.md](traceability.md) for section-by-section coverage,
[divergences.md](divergences.md) for the accepted departures from SQL/MP.

### Statements implemented

`ROLLBACK WORK` · `INSERT` · `SELECT … INTO` (single-row) · `UPDATE` (searched) ·

### Host variable types implemented

`char[n]` fixed · VARCHAR struct (`len`/`val` pair, tagged or anonymous) ·
`short` · `int` · `long` · `long long` · `float` · `double` · indicators
(`short`) · `CHARACTER SET` clauses · C comments inside a declare section ·
tagged records generated by `INVOKE`

Widths come from the host's own `sizeof`, not from a table — the fix for the
Gate 7 defect where a hand-declared `long` failed its own `_Static_assert` on
LP64. `DIV-001` records the consequence.

### Structures

| Structure | Size | Source of layout |
|---|---|---|
| `SQLCA` | 430 bytes | Total published; field layout is **private** — `DIV-041`. The manual gives no layout anywhere, so none can be conformed to |
| `SQLSA` | 838 (v300) / 1790 (v330) | §9 pp.9-15..9-16 publish both; both validate exactly under packing. Registered, not accessor-mediated, because programs index the fields by name |
| `SQLDA` | header 4; `sqlvar` 40 | §10 p.10-7 publishes a 24-byte `sqlvar`; `DIV-040` widens the address fields to 64 bits, and `DIV-058` records that this moves `sqlvar` from offset 4 to offset 8 |

Every externally visible offset carries a `_Static_assert`, per Principle VI.
`tests/harness/sqlsa_layout_sync.sh` and `sqlda_layout_sync.sh` check the
emitted offsets against the spec constants — currently 36 and 12 offsets agree.

## 3. What is owed

### Blocked on external documents

Three documents gate real work. Under the phase-entry rule as amended
2026-09-03, a phase may begin while its predecessor's remaining criteria are
blocked *solely* on an external dependency — provided each blocked item is named
as a standing debt. These are those debts.

| Document | What it decides | Blocks |
|---|---|---|
| `SQLRM` (SQL/MP Reference Manual) | Statement syntax and semantics outside the C manual's scope | DML outside `BEGIN WORK` and nested `BEGIN WORK` (003 Q1, Q2); implicit open lifecycle (003 Q3); single-row `SELECT` matching many rows (004 Q2); cursor stability access modes (004 Q3, 008 Q5); the conversion warning codes behind `DIV-042` (002 Q1, 005 Q4) |
| `CPG` (C compiler pragma set) | Whether NonStop C's `fixed` type is a real type or a compiler extension | `ESQLC_T_DECIMAL` and the whole DECIMAL path (002 Q3) |
| `sqlh` (published header) | The character-set ID values the `SQLDA` carries in `precision` | Character-set IDs (002 Q7); slice decision SD-1's final form |

Also outstanding, but not a document this project can fetch: the **SQL message
file**, which decides what `SQLCADISPLAY` and `SQLSADISPLAY` actually print
(005 Q6).

### Not blocked — simply not built

Positioned `UPDATE`/`DELETE` and `WHERE CURRENT OF` (refused inside their
handlers, since they are clauses rather than keywords the dispatch table can
see) · `EXECUTE IMMEDIATE` · `DESCRIBE INPUT` · dynamic cursors · legacy v1/v2
`SQLDA` descriptors · `SETSCALE` · `TYPE AS` · `SQL SOURCE` · DDL, DCL and DSL ·
`CONTROL TABLE`/`CONTROL QUERY` · `LOCK`/`UNLOCK`/`FREE`/`GET` · the 22 CPRL
collation procedures · the SQLCA/SQLSA access procedures beyond
`SQLCAGETINFOLIST` · and the whole of feature 008 (Guardian naming, TACL
DEFINEs, PAID, VSBB, program invalidation, version management, `SQLMEM`,
Pathway, Appendices B and C).

Every one of these refuses loudly today rather than no-opping — that is
Principle III, and `tests/harness/run_negative.sh` has 35 assertions that say so.

## 4. Divergences

19 registered in [divergences.md](divergences.md), each with Status, NonStop,
Here, Rationale, Detection and Migration. The audit confirms no entry is missing
a field and none is unreferenced by a spec.

| | |
|---|---|
| `DIV-001` | Host variable integer widths taken from the host's `sizeof` |
| `DIV-002` | TACL DEFINE name resolution — unresolved, high blast radius |
| `DIV-010` | TMF transactions on InnoDB |
| `DIV-011` | `SQLSA` statistics without a NonStop executor |
| `DIV-012` | PROGID privilege elevation is refused |
| `DIV-020` | No SQL program objects, invalidation, or recompilation |
| `DIV-030` | TNS memory placement pragmas accepted and ignored |
| `DIV-040` | `SQLDA` address fields widened to 64 bits |
| `DIV-041` | `SQLCA` layout is implementation-private |
| `DIV-042` | Conversion warning codes are chosen, not inherited |
| `DIV-050` | `INVOKE` indicator-name collision is diagnosed, not reproduced |
| `DIV-051` | Post-`DELETE` cursor position pinned to one of two permitted outcomes |
| `DIV-052` | MariaDB strips trailing blanks from `CHAR` on retrieval |
| `DIV-053` | `CLIENT_FOUND_ROWS`, and rows found versus rows altered |
| `DIV-054` | SQL error 8300 without its file-system detail |
| `DIV-055` | Character-set mapping, and byte-verbatim binding |
| `DIV-056` | The 30/31-character indicator collision is diagnosed, not reproduced |
| `DIV-057` | The names buffer's 8-byte table-name budget |
| `DIV-058` | Widening the `SQLDA` moves `sqlvar` off the published header length |

The three that most shape observable behaviour:

- **`DIV-041`** — the `SQLCA`'s layout is private. The manual documents its
  contents only indirectly, through `SQLCAGETINFOLIST` item codes, and never as
  a field list. A program that indexes `SQLCA` fields by offset was relying on
  something the manual never published.
- **`DIV-055`** — binding is byte-verbatim, achieved by setting
  `character_set_client = binary`. This corrected Gates 1–7, which had been
  letting the connection charset transform data in flight.
- **`DIV-040`** / **`DIV-058`** — the `sqlvar` grows from 24 to 40 bytes because
  a 16-bit field cannot hold a 64-bit pointer, and the raised alignment then
  moves `sqlvar` from offset 4 to offset 8. Programs that compute
  `sizeof(SQLDA) + n * 24` will under-allocate.

## 5. How this is kept true

The claims above are checked, not asserted. `/speckit.analyze` runs eight
principle audits plus a cross-feature pass:

| Harness | Checks |
|---|---|
| `citation_check.py` | All 164 manual citations resolve to the cited page |
| `abi_isolation.sh` | Emitted C compiles with no MariaDB header reachable |
| `contract_sync.sh` | Every `esqlc_*` signature in a plan exists in the 003 contracts |
| `sqlsa_layout_sync.sh`, `sqlda_layout_sync.sh` | Emitted offsets match the spec constants |
| `diag_registry.sh` | Every emitted code is registered; no code marked unreachable is emitted |
| `spec_assertions.py` | 192 assertions over emitted C |
| `run_negative.sh` | 35 refusals fire for the right reason |
| `run_tier2.sh` | 60 assertions against a live server |

Guards are proven load-bearing by mutation testing rather than by inspection.
That has repeatedly paid: Gate 5's surviving mutation exposed an assertion that
could not detect a missing reset, and Gate 8's exposed an entire runtime
component (`src/rt/charset.c`) that nothing called — deleted rather than wired up.

Two known limitations of the checks themselves: 2 of 164 citations are
*unverifiable* rather than verified, because PDF text extraction dropped the
page footer (§2 p.2-11, §11 p.11-2); and the citation checker skips entirely
when `manual/` is absent, which is the CI case.
